## 1. Vue 2 响应式原理如何实现？有什么缺陷？

### 参考答案

Vue 2 的响应式原理是通过 Object.defineProperty() API 递归劫持对象的属性，将其转化为 getter/setter，在属性访问时收集依赖（Watcher），在属性修改时触发依赖更新，从而实现数据变化到视图更新的联动

核心缺陷及原因分析：
1无法检测对象属性增删 Object.defineProperty 只能劫持已存在的属性 this.obj.newProp = val 不会触发更新
2. 数组索引修改无法检测 出于性能考虑未对数组索引进行劫持 arr[0] = 1 无效
3. 深层对象性能消耗大 初始化时递归遍历所有属性转化为响应式 大对象初始化卡顿
4. 嵌套结构更新冗余 父/子对象更新可能触发不必要渲染 性能浪费

解决方案：
1. 动态添加响应式属性
Vue.set(this.obj, 'newProp', value);
2. 数组索引更新
this.$set(this.arr, index, newValue);
this.arr.splice(index, 1, newValue);
3. 性能优化：冻结大对象
this.largeData = Object.freeze({ ... });

## 2. Vue 3 为什么用 Proxy 替代 defineProperty？

### 参考答案

Proxy 的引入是为了从根本上解决 Vue 2 基于 Object.defineProperty 的响应式系统在动态属性增删、数组索引修改和初始化性能方面的缺陷，同时为更细粒度的依赖追踪和跨平台能力提供基础支持。

Vue 2 defineProperty 的核心痛点：
1. 动态属性限制 新增/删除属性必须使用 Vue.set/Vue.delete defineProperty 只能劫持已存在属性
2. 数组监控缺陷 通过下标修改元素 (arr[0]=1) 或修改 length 无效 未对数组索引进行劫持
3. 初始化性能瓶颈 递归遍历整个对象并转化所有属性，大对象初始化卡顿 初始化即执行全量劫持
4. 嵌套对象冗余更新 深层嵌套对象任意层级修改都会触发根级更新 依赖收集粒度粗放

Proxy 的四大核心优势：
优势 1：全面的拦截能力：
动态属性支持：自动检测新增/删除属性
完整数组监控：下标修改、length 变化均可捕获
符号键名(Symbol)支持：defineProperty 无法劫持 Symbol 键
优势 2：惰性劫持与按需递归
性能提升：仅当访问到嵌套对象时才创建代理，避免初始化全量递归
内存优化：未访问的属性不创建响应式关联
优势 3：细粒度依赖追踪：
Vue 2：整个对象对应一个 Dep（依赖管理器）
Vue 3：每个属性关联独立 Dep
精准更新：修改 obj.a 时不会触发依赖 obj.b 的组件
优势 4：原生支持集合类型
可直接代理 Map、Set、WeakMap 等集合类型
Vue 2 需特殊封装才能实现响应式集合

## 3. 虚拟 DOM 的作用是什么？

### 参考答案

①跨平台渲染 ② 批量更新减少 DOM 操作 ③ 通过 Diff 算法最小化更新范围。
虚拟 DOM 的本质是 用 JS 计算成本换取 DOM 操作成本 的 trade-off 设计，其价值体现在三个维度：
性能维度：通过 Diff 算法和批量更新，解决频繁操作 DOM 的性能瓶颈
架构维度：抽象渲染过程，实现跨平台能力的一次编写多端运行
工程维度：降低前端开发心智负担，推动声明式编程范式普及

值得注意的是，随着现代浏览器优化和编译技术进步，虚拟 DOM 不再是性能银弹，但作为 框架设计的中介层，其架构价值远大于性能价值。这也是为什么 Vue 3 在保留虚拟 DOM 的同时，引入编译时优化实现性能突破。

## 4. Diff 算法中 key 的作用是什么？

### 参考答案

Vue 框架中 key 的作用：
1. ‌节点复用识别‌：通过 key 判断新旧虚拟 DOM 节点是否为同一节点，避免重复创建 DOM 元素。例如列表渲染时，若元素带有唯一 key（如数据项的 ID），Vue 可复用现有节点而非重新创建。
2. 优化列表渲染‌：在动态列表中，key 帮助快速定位需要更新的节点，减少不必要的 DOM 操作（如删除、移动等）。例如删除列表项时，Vue 可直接移除对应节点而非重建整个列表。
3. ‌避免状态混乱‌：避免因节点复用导致子组件状态或临时 DOM 状态（如表单输入值）丢失。

## 5. 为什么 Vue 组件 data 必须是函数？

### 参考答案

确保组件实例数据隔离：
组件需支持复用，每个实例应维护独立的数据状态。若 data 为对象，所有实例会共享同一份数据，导致数据冲突。 ‌
函数返回独立数据副本：
通过函数返回新对象，每次创建组件实例时都会生成独立的数据副本，实现组件间数据隔离。
避免全局污染：
函数返回的对象与外部状态无关，防止外部修改影响组件实例数据，确保组件内部状态可控。

## 10. Vue 3 新特性 ref 和 reactive 的区别？

### 参考答案

ref：
基本用法：ref 用于创建一个包含基本数据类型的响应式引用。这意味着你可以用它来创建一个响应式的变量，比如一个数字、字符串或布尔值。
访问方式：通过 .value 属性来访问和修改ref的值。例如，如果你有一个 ref 变量 count，则通过 count.value 来访问或修改它的值。
适用场景：当你需要声明一个单独的响应式变量时使用ref，特别是当这个变量是基本类型（如字符串、数字、布尔值）时。
reactive
基本用法：reactive 用于创建一个包含对象（或数组）的响应式对象。这意味着你可以用它来创建一个响应式的对象或数组。
访问方式：直接通过属性名来访问和修改reactive对象的属性。例如，如果你有一个 reactive 对象 state，则直接通过 state.property 来访问或修改它的属性。
适用场景：当你需要声明一个包含多个属性的响应式对象时使用reactive，特别是当这些属性是相互关联的复杂数据结构（如对象或数组）时。

## 11. watch 和 watchEffect 的区别？

### 参考答案

监听方式：‌
watch需显式指定依赖源（如ref定义的数据或函数返回值），而watchEffect自动收集组件内所有依赖的响应式数据变化
‌初始执行时机：‌
watch默认不立即执行回调（除非配置immediate: true），而watchEffect在组件初始化时立即执行。
返回值处理：‌
watch可获取新旧值（通过新旧值对比逻辑），watchEffect仅能获取当前值。
适用场景：
watch‌：适用于需要精准控制监听源和执行时机的场景，例如：
用户信息更新（如昵称修改后页面实时更新） ‌
复杂表单验证（如邮箱格式校验触发按钮状态变化） ‌
数据联动更新（如商品类别选择影响价格筛选条件）
‌watchEffect‌：适用于自动追踪依赖且无需手动指定依赖源的场景，例如：
组件初始化时执行副作用（如计算缓存数据） ‌
响应式引用变化（如对象属性修改触发相关逻辑）
watch因明确依赖源而性能更优，watchEffect可能因自动收集依赖导致性能开销增加，但简化代码编写

## 12. Vite 为什么比 Webpack 快？

### 参考答案

Vite 比 Webpack 快的主要原因在于其采用原生 ESM 模块按需加载机制和增量构建策略，结合 esbuild 工具的高效编译能力，显著减少了启动时间和编译成本
开发模式差异：
Vite在开发阶段采用‌按需编译‌模式，仅编译被修改的文件，而Webpack需重新打包整个项目。例如修改单个文件时，Vite仅处理改动部分，而Webpack需重建全部依赖链。
ESM原生支持：
Vite直接利用浏览器对ESM（ ECMAScript Module ）的支持实现模块动态加载，避免Webpack的全量打包。当文件修改后，仅更新相关模块，无需全量刷新页面
底层技术优化：
Vite使用 Go语言 开发的esbuild工具进行依赖预构建和增量编译，相比Webpack的 JavaScript 单线程处理，效率提升显著（如代码压缩速度提升20倍以上）。

## 27. 闭包原理与应用场景

### 参考答案

原理
闭包由函数及其词法环境组成，当内部函数引用外部函数的局部变量时，即使外部函数执行结束，内部函数仍可通过闭包机制访问这些变量。例如，在外部函数中定义内部函数并返回该内部函数，此时内部函数会持续持有外部函数的词法作用域引用
常见应用场景：
1. ‌模块化与私有变量
通过闭包封装模块的私有变量，避免全局污染。例如，创建计数器模块时，内部变量value仅能通过模块提供的方法访问，外部无法直接修改。
2. 高阶函数与回调
闭包可用于传递函数作为参数，实现复杂逻辑的封装。例如，将带有参数的函数作为回调传递给异步操作。
3. 持久化变量
闭包可保持变量在内存中不被垃圾回收，适用于需要长期保存数据的情况（如缓存）。
闭包可能导致内存泄漏，尤其是当内部函数引用外部变量且外部作用域未被销毁时

## 29. 原型链继承

### 参考答案

原型链继承是 JavaScript 中基于原型对象实现继承的机制，通过将子类构造函数的原型（prototype）指向父类实例，建立原型链连接，使子类实例能够访问父类属性和方法。
具体过程：
1. 建立原型连接：
Child.prototype = new Parent()
此时 Child.prototype.__proto__ === Parent.prototype
2. 修复构造函数指向：
Child.prototype.constructor = Child
（避免原型链断裂）
3. 创建子类实例：
const child = new Child()
4. 原型链查找：
访问 child.property 时：
先在 child 自身查找
未找到则通过 __proto__ 查找到 Parent 实例
仍未找到则继续查找到 Parent.prototype

## 30. 防抖与节流

### 参考答案

防抖（Debounce）和节流（Throttle）是前端开发中常用的性能优化技术，主要用于控制高频事件触发频率，区别在于：
核心差异：
‌防抖‌：触发事件后延迟执行函数，若在延迟期间再次触发则重新计时。适用于搜索框输入、窗口尺寸调整等场景，避免重复请求或重绘。 ‌
‌节流‌：规定时间内无论触发多少次事件，仅执行一次函数。适用于滚动事件监听、拖拽操作等需要固定响应频率的场景。
典型应用场景：
‌防抖场景‌
用户输入搜索关键词时，仅在停止输入后发起请求。 ‌
调整浏览器窗口大小后，延迟重新计算页面布局。 ‌
表单提交时防止重复点击按钮
‌节流场景‌
页面滚动时按固定频率触发事件（如懒加载图片）。 ‌
鼠标移动或拖拽元素时限制更新频率。

// 防抖：连续触发只执行一次
function debounce(fn, delay) {
  let timer;
  return function() {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, arguments), delay);
  }
}

// 节流：固定时间执行一次
function throttle(fn, delay) {
  let flag = true;
  return function() {
    if (!flag) return;
    flag = false;
    setTimeout(() => {
      fn.apply(this, arguments);
      flag = true;
    }, delay);
  }
}

## 34. 子组件可以直接改变父组件的数据吗？

### 参考答案

子组件不可以直接改变父组件的数据。这样做主要是为了维护父子组件的单向数据流。每次父级组件发生更新时，子组件中所有的 prop 都将会刷新为最新的值。如果这样做了，Vue 会在浏览器的控制台中发出警告。
Vue提倡单向数据流，即父级 props 的更新会流向子组件，但是反过来则不行。这是为了防止意外的改变父组件状态，使得应用的数据流变得难以理解，导致数据流混乱。如果破坏了单向数据流，当应用复杂时，debug 的成本会非常高。
只能通过 $emit 派发一个自定义事件，父组件接收到后，由父组件修改。

## 38. 说一下Vue的生命周期

### 参考答案

1. beforeCreate（创建前）；2、created（创建后）；3、beforeMount（挂载前）；4、mounted（挂载后）；5、beforeUpdate（更新前）；6、updated（更新后）；7、beforeDestroy（销毁前）；8、beforeDestroy（销毁前）。另外还有 keep-alive 独有的生命周期，分别为 activated 和 deactivated 。用 keep-alive 包裹的组件在切换时不会进行销毁，而是缓存到内存中并执行 deactivated 钩子函数，命中缓存渲染后会执行 activated 钩子函数。

## 39. 一般在哪个生命周期请求异步数据

### 参考答案

我们可以在钩子函数 created、beforeMount、mounted 中进行调用，因为在这三个钩子函数中，data 已经创建，可以将服务端端返回的数据进行赋值。推荐在 created 钩子函数中调用异步请求，因为在 created 钩子函数中调用异步请求有以下优点：1、能更快获取到服务端数据，减少页面加载时间，用户体验更好；2、SSR不支持 beforeMount 、mounted 钩子函数，放在 created 中有助于一致性。

## 40. v-if和v-show的区别

### 参考答案

手段：v-if是动态的向DOM树内添加或者删除DOM元素；v-show是通过设置DOM元素的display样式属性控制显隐；编译过程：v-if切换有一个局部编译/卸载的过程，切换过程中合适地销毁和重建内部的事件监听和子组件；v-show只是简单的基于css切换；编译条件：v-if是惰性的，如果初始条件为假，则什么也不做；只有在条件第一次变为真时才开始局部编译; v-show是在任何条件下，无论首次条件是否为真，都被编译，然后被缓存，而且DOM元素保留；性能消耗：v-if有更高的切换消耗；v-show有更高的初始渲染消耗；使用场景：v-if适合运营条件不大可能改变；v-show适合频繁切换。

## 41. vue中data为什么是一个函数而不是对象

### 参考答案

Vue组件可能存在多个实例，如果使用对象形式定义data，则会导致它们共用一个data对象，那么状态变更将会影响所有组件实例，这是不合理的；采用函数形式定义，在initData时会将其作为工厂函数返回全新data对象，有效规避多实例之间状态污染问题。而在Vue根实例创建过程中则不存在该限制，也是因为根实例只能有一个，不需要担心这种情况
